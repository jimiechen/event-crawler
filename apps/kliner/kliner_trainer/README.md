# K线双盲训练系统

## 项目简介

K线双盲训练系统是一个基于 Flutter 开发的股票K线训练应用，帮助用户通过双盲训练提高股票交易技能。

## 核心功能

### 1. 仓位管理
- **1层 = 1万（10000元）**
- **3层 = 3万（30000元）**
- **5层 = 5万（50000元）= 满仓**
- 起始资金：100000元
- 使用收盘价作为买入/卖出价格
- 允许清仓（卖出超过买入仓位）

### 2. 收益率计算
- 买入时记录买入价格（使用当天收盘价）
- 卖出时使用当天收盘价计算收益率
- 观望时计算当前持仓收益率
- 收益率以百分比形式显示
- 正收益：红色
- 亏损：绿色
- 平盘：灰色

### 3. 随机算法
- 随机选择任意时间段的股票数据
- 不限制年份范围
- 避免K线越界

### 4. UI 优化
- 仓位按钮显示"1万"、"2万"、"3万"、"4万"、"5万"
- 当前仓位显示"X万"格式
- K线图占主屏幕大部分（flex: 8）
- 添加了关闭按钮（右上角）
- 移除了操作理由输入框
- 移除了"下一天"按钮

### 5. 自动跳转
- 操作后自动调用 `nextDay()`
- K线往后移动1天
- 显示下一天的K线数据

### 6. K线图功能
- 支持放大缩小（10-60根K线）
- 左下角有左右切换按钮
- 每次操作后K线往后移动1天
- 显示EXPMA5、EXPMA13指标
- 显示成交量指标（初学者模式）
- 显示地量信号

### 7. 难度模式
- **初学者模式**：显示全部指标，60天数据
- **中级模式**：隐藏成交量指标，40天数据
- **高级模式**：只显示K线，30天数据
- **大师模式**：完全双盲，20天数据

### 8. 技术信号
- **金叉**：EXPMA5上穿EXPMA13，看涨信号
- **死叉**：EXPMA5下穿EXPMA13，看跌信号
- **地量**：成交量低于60日均量一半，可能变盘
- **强烈买入**：金叉+地量
- **买入**：金叉
- **卖出**：死叉
- **观望**：其他情况

### 9. 训练流程
1. 开始训练：随机选择股票和起始天数
2. 按天逐步进行：每次操作后自动跳转到第二天
3. 执行操作：买入、卖出、观望
4. 计算收益率：实时反映当前持仓收益
5. 显示复盘：显示操作结果和技术信号
6. 结束训练：显示最终总结

### 10. 数据统计
- 训练次数
- 得分统计
- 当前资金
- 持仓市值
- 收益率显示
- 操作历史记录

## 技术栈

- **Flutter**：跨平台移动应用框架
- **GetX**：状态管理和路由管理
- **CSV Data**：股票数据存储和读取
- **EXPMA**：指数移动平均线指标计算
- **成交量**：成交量指标计算

以下是结合“手”的单位限制后，对原有规则的修正方案：

### 📝 规则调整对比

为了使您更清晰地看到变化，下表对比了调整前后的核心规则差异：

| 规则维度 | **调整前（理想化）** | **调整后（符合实盘）** |
| :--- | :--- | :--- |
| **1. 买入单位** | 可按资金比例计算任意金额。 | **必须以“手”为单位**。A股主板/创业板1手为100股，科创板为200股。买入数量必须是1手（100股）的整数倍。 |
| **2. 买入计算逻辑** | `买入资金 = 总资金 × 仓位比例`<br>`可买股数 = 买入资金 / 股价` | `计划买入资金 = 总资金 × 仓位比例`<br>`**可买手数 = (计划买入资金 / 股价 / 100).floor()` // 向下取整到整手数<br>`**实际买入资金 = 可买手数 × 100 × 股价` |
| **3. 卖出单位** | 可按仓位比例卖出任意市值。 | 卖出时，如果持仓中有不足1手的零股（例如因送转股产生），可以一次性卖出。否则，也应尽量以手为单位操作。 |
| **4. 资金与仓位匹配** | 仓位比例严格等于资金占用比例。 | **仓位比例变为“目标”**。实际资金占用和仓位层级由**可成交的整手数反向决定**，可能与目标有细微偏差。 |
| **5. 系统更新关键** | 直接按比例扣减资金。 | 以**实际买入资金**扣减可用资金，并以**实际买入股数**更新持仓。 |

### 💻 实现逻辑调整示例
以“10万资金，用3层仓（6万元）买入某股票（当前价10元/股）”为例，调整后的代码逻辑应为：

```dart
// 计算目标资金和理论股数
double targetCapital = totalCapital * 0.6; // 6万元
double stockPrice = 10.0; // 当前股价
// 关键调整：计算最大可买手数（向下取整）
int maxShares = (targetCapital / stockPrice).floor(); // 理论最多6000股
int tradableLots = (maxShares / 100).floor(); // 可买60手
int actualShares = tradableLots * 100; // 实际可买6000股
double actualCapitalUsed = actualShares * stockPrice; // 实际占用资金 6万元

// 更新状态
availableCash -= actualCapitalUsed; // 可用资金减少6万
holdingShares += actualShares; // 持仓增加6000股
currentPositionValue = holdingShares * stockPrice; // 持仓市值更新为6万
// 注意：此时实际仓位 = 6万 / 10万 = 60%，依然符合3层仓的目标
```
**卖出操作**也需类似调整，根据用户指定的卖出仓位比例，先计算目标卖出市值，再转换为可卖出的**整手数**（若有零股则一次性卖出），最后按实际卖出股数结算资金和盈亏。

### ⚠️ 新增的边界情况
1.  **资金不足1手**：当 `目标资金 < 1手股票市值` 时，即使选择“1层仓”也无法买入，系统应提示“资金不足最小交易单位”。
2.  **仓位偏差反馈**：在界面显示“**目标仓位：3层 (6万元)，实际成交：60手 (6万元)**”，让用户明确知晓。
3.  **零股处理**：在模拟中，若遇到分红送转产生零股（如150股），应允许用户**一次性全部卖出**，但不能再买入零股。

**总结**：加入“手”的单位限制后，系统的核心变化是：**从“按资金比例驱动”变为“按可交易整手数驱动”**。这会使模拟更贴近真实交易，增加训练的实战性。
