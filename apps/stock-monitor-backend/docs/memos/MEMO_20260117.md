# 2026-01-17 系统优化备忘录 & 验收指南

## 1. 核心变更摘要

本次优化主要解决了问财股票池的数据入库、基础分计算及排名逻辑问题，确保了"问财上榜即入库计算"的需求落地。

### 1.1 数据库模型调整
*   **`StockScoreResult` 表结构优化**:
    *   新增 `daily_score` (每日得分): 存储当天的动态评分（基于量价异动标签）。
    *   新增 `accumulated_score` (累计得分): 存储历史累计总分。
    *   保留 `total_score` (兼容字段): 逻辑上等同于 `accumulated_score`，保证旧代码兼容性。
    *   明确 `pool_type`: 区分 `wencai` (问财池) 和 `self_selected` (自选池)。

### 1.2 业务逻辑优化
*   **问财数据入库 (Wencai Ingestion)**:
    *   `WencaiCrawler` 抓取数据后，立即调用 `WencaiService.save_stocks`。
    *   `save_stocks` 会自动创建/更新 `StockInfo` (标记 `source='wencai'`)。
    *   **关键触发**: 入库时自动检测并触发 "历史基础分 (Historical Baseline)" 计算，确保首日上榜股票拥有初始分。
*   **评分引擎 (Rule Engine)**:
    *   采用 **累计分 (Accumulated Score)** 逻辑: 当日总分 = 前一日累计分 + 当日每日分。
    *   **自愈机制 (Self-Healing)**: 如果缺少前一日分数（如首日上榜或数据断档），自动回溯 250 天历史数据计算基础分作为起点。
*   **排名计算 (Ranking)**:
    *   支持 **分池排名**: `wencai` 池和全市场池分别计算排名，确保问财池内部排名准确。

### 1.3 数据回溯
*   执行了全量历史回溯脚本 (`scripts/sync_wencai_history.py`)。
*   覆盖日期: 2025-11-20 至 2026-01-16。
*   所有历史问财上榜股票均已入库并计算了当天的基础分/累计分。

## 2. 定时任务与计算服务逻辑

### 2.1 定时任务列表 (SchedulerService)

| 任务名称 | 执行时间 | 逻辑描述 |
| :--- | :--- | :--- |
| `crawl_wencai_data` | 每日 15:05 | 1. 爬取问财数据<br>2. 保存 `StockInfo` & `WencaiStock`<br>3. **触发新股基础分计算** |
| `sync_stock_daily` | 每日 15:15 | 同步全市场日线数据 (价格/成交量) |
| `calculate_daily_scores`| 每日 15:30 | 1. 生成量价异动标签 (Volume Tags)<br>2. `RuleEngineService` 计算每日分 & 累计分<br>3. 更新 `StockScoreResult` |
| `calculate_rankings` | 每日 16:00 | 1. 按 `pool_type` 分组 (wencai/all)<br>2. 根据 `accumulated_score` 降序排名<br>3. 更新 `ranking` 字段 |

### 2.2 计算服务逻辑详情

#### A. 基础分计算 (Baseline Calculation)
*   **触发场景**: 新股入库、历史数据缺失自愈。
*   **逻辑**: 回溯过去 250 天 (SCORE_WINDOW_DAYS)，累加所有有效异动标签分数。
*   **实现**: `VolumeAnalysisService.calculate_historical_baseline`。

#### B. 每日动态分 (Daily Scoring)
*   **触发场景**: 每日收盘后。
*   **逻辑**:
    1. `VolumeAnalysisService` 分析当日行情，生成 Tags (如 `vol_3x` 3倍量, `land_vol_60` 60日地量)。
    2. `RuleEngineService` 读取 Tags，映射为 `daily_score`。
    3. 读取前一日 `accumulated_score` (或计算 Baseline)，加上 `daily_score` 得到今日总分。
