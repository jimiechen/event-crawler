# Trae AI多模型协作文档规范

## 一、文档类型

系统支持以下四种文档类型：

1. **每日进度** (`daily_progress`)
   - 记录每日完成的工作内容
   - 文件命名: `daily_progress_YYYYMMDD.md`
   - 存放目录: `collaboration_docs/daily_progress/`

2. **周报** (`weekly_report`)
   - 汇总每周工作进展
   - 文件命名: `weekly_report_YYYYMMDD.md`
   - 存放目录: `collaboration_docs/weekly_report/`

3. **技术方案评审** (`technical_review`)
   - 评审技术方案和架构设计
   - 文件命名: `technical_review_YYYYMMDD.md`
   - 存放目录: `collaboration_docs/technical_review/`

4. **测试报告** (`test_report`)
   - 记录测试结果和问题
   - 文件命名: `test_report_YYYYMMDD.md`
   - 存放目录: `collaboration_docs/test_report/`

## 二、Markdown文档结构

所有协作文档必须遵循以下结构：

```markdown
# [文档标题]

## 元数据
- 创建时间: YYYY-MM-DD HH:MM:SS
- 最后更新: YYYY-MM-DD HH:MM:SS
- 当前模型: DeepSeek/GLM4.7/Gemini
- 文档版本: v1.0
- 文档类型: [daily_progress/weekly_report/technical_review/test_report]

## 内容
[实际内容]

## 变更记录
- [时间] @ModelName: [变更描述]
```

## 三、署名规范

### 3.1 署名格式
每次更新文档时，必须在"变更记录"部分添加署名：

```
[YYYY-MM-DD HH:MM] @ModelName: [操作描述]
```

### 3.2 署名示例

```markdown
## 变更记录
- [2026-01-14 10:30] @GLM4.7: 创建文档
- [2026-01-14 11:15] @DeepSeek: 添加架构分析
- [2026-01-14 14:20] @Gemini: 完善技术细节
- [2026-01-14 16:45] @GLM4.7: 整合各方意见
```

### 3.3 署名规则
- 时间格式必须为 `YYYY-MM-DD HH:MM`
- 模型名称必须是 `DeepSeek`、`GLM4.7` 或 `Gemini`
- 操作描述必须简明扼要，说明本次更新的主要内容
- 署名按时间倒序排列（最新的在最上面）

## 四、文件命名规范

### 4.1 命名规则
所有文档文件名必须遵循以下格式：

```
[文档类型]_[日期].md
```

### 4.2 日期格式
- 日期格式: `YYYYMMDD`
- 示例: `20260114` 表示 2026年1月14日

### 4.3 命名示例

```bash
daily_progress_20260114.md
weekly_report_20260114.md
technical_review_20260114.md
test_report_20260114.md
```

## 五、内容规范

### 5.1 中文要求
- 所有文档必须使用中文编写
- 代码注释和文档字符串必须使用中文
- 技术术语可以保留英文

### 5.2 结构要求
- 使用Markdown标准语法
- 标题层级清晰（最多不超过3级）
- 代码块必须指定语言类型
- 表格必须有表头

### 5.3 内容质量
- 内容必须准确、完整
- 避免冗余和重复
- 逻辑清晰，条理分明
- 必要时添加示例和说明

## 六、版本管理

### 6.1 版本号格式
- 主版本号.次版本号.修订号
- 示例: `v1.0.0`

### 6.2 版本更新规则
- 主版本号：重大架构变更
- 次版本号：功能新增或修改
- 修订号：bug修复或小改动

### 6.3 备份机制
- 每次更新前自动备份旧版本
- 备份文件名: `[原文件名].[时间戳].bak`
- 保留最近10个备份版本

## 七、协作流程

### 7.1 基本流程
1. GLM4.7/Gemini读取项目文档和代码
2. 通过MCP工具调用DeepSeek获取外部视角
3. 整合DeepSeek的建议和本地项目情况
4. 更新协作文档并添加署名
5. 循环直到达成共识

### 7.2 协作规则
- 每个模型必须遵循本规范
- 更新前必须添加署名
- 遇到分歧时通过讨论解决
- 最终文档必须达成共识

```markdown
## 元数据
- 创建时间: 2026-01-14 10:00:00

- 当前模型: Gemini

3. 实现Cookie管理
4. 支持异步操作

### 评审意见
- ✅ 架构设计合理
- ✅ 错误处理完善
- ⚠️ 建议添加重试机制
- ⚠️ 建议优化性能

### 改进建议
1. 添加请求限流
2. 实现断点续传
3. 优化等待策略

## 变更记录
- [2026-01-14 16:00] @Gemini: 完成技术方案评审
- [2026-01-14 14:30] @DeepSeek: 提供架构分析
- [2026-01-14 10:00] @GLM4.7: 创建评审文档
```

## 九、注意事项

1. **安全性**
   - 不要在文档中记录敏感信息（密码、密钥等）
   - 使用环境变量管理配置

2. **可维护性**
   - 保持文档结构清晰
   - 及时更新文档内容
   - 定期归档旧文档

3. **协作性**
   - 尊重其他模型的意见
   - 主动沟通和讨论
   - 共同维护文档质量
