# 股票池业务逻辑与数据流向梳理

## 1. 核心业务概述

本系统核心业务并非全市场监控（5000+只股票），而是基于**精选股票池**的实时监控。
核心逻辑：**问财/自选股 -> 股票池 (MonitorList) -> 同花顺实时数据 -> Baseline 策略计算 -> 告警**。

## 2. 股票池组成 (Stock Pool Composition)

股票池 (`MonitorList`) 是系统进行实时监控的唯一依据。主要由以下两个数据源组成：

### 2.1 问财数据 (Wencai Data)
- **来源**: 同花顺问财 (Wencai) 选股结果。
- **机制**:
  1. 通过 `WencaiService` 解析问财页面或接口数据。
  2. 数据存入 `wencai_stocks` 表作为原始记录。
  3. **同步机制**: 将筛选出的股票同步至 `monitor_list` 表，并可设置为 `is_active=True` (活跃监控)。
- **特点**: 动态更新，反映市场热点。

### 2.2 手动录入 (Manual Entry)
- **来源**: 用户手动添加的自选股。
- **机制**: 直接写入 `monitor_list` 表。
- **特点**: 长期关注，稳定性高。

> **注意**: `monitor_list` 表中的 `is_active` 字段决定了该股票是否参与实时监控循环。非活跃股票不会消耗实时数据接口资源。

## 3. 业务数据流向 (Data Flow)

### 3.1 实时监控循环 (Real-time Monitor Loop)
由 `MonitorEngine` (监控引擎) 驱动，默认每 **5秒** 执行一次循环 (可配置)。

```mermaid
graph TD
    A[MonitorEngine] -->|1. 获取活跃列表| B(MonitorList Table)
    B -->|返回 is_active=True 的股票| A
    A -->|2. 请求实时数据| C{同花顺实时接口}
    C -->|推送/返回 Ticks 数据| A
    A -->|3. 调用策略分析| D[StrategyService]
    D -->|4. 计算 Baseline| E{是否触发规则?}
    E -->|Yes| F[触发告警 (Alert)]
    E -->|No| G[忽略]
```

### 3.2 Baseline 规则计算 (Baseline Logic)
`StrategyService` 对每条实时 Tick 数据进行规则判定。只有同时满足以下条件时，才会被判定为"异动"并触发告警：

1.  **量比 (Volume Ratio) > 3.0**
    *   反映当前成交量相对于过去5日均量的放大程度。
2.  **涨幅 (Price Change) > 3.0%**
    *   反映价格的瞬时拉升强度。

### 3.3 数据落地与告警
- **告警**: 满足 Baseline 规则后，系统会记录 `trigger_log` 并通过配置的渠道（如日志、弹窗等）发出提醒。
- **冷却**: 为防止重复告警，同一只股票在一定时间内（如5分钟）不会重复触发相同类型的告警。

## 4. 全量与增量同步任务辨析

基于上述股票池逻辑，系统的定时任务（全量/增量）含义如下：

*   **全量数据同步**:
    *   **对象**: 仅针对 **股票池 (MonitorList)** 中的股票，而非全市场。
    *   **逻辑**: 优先加载本地 CSV 历史数据 (最近250日)，确保 Baseline 计算有足够的历史基准。
*   **增量数据同步**:
    *   **对象**: 同样仅针对 **股票池**。
    *   **逻辑**: 调用 Tushare 等接口补充当日或缺失的最新K线数据。

## 5. 总结
本系统是一个**漏斗型**监控系统：
1.  **漏斗口**: 问财选股/人工自选 (入池)。
2.  **过滤器**: `MonitorList` (激活)。
3.  **实时流**: 同花顺 Ticks。
4.  **核心筛**: Baseline (量比>3 & 涨幅>3%)。
5.  **产出物**: 异动告警。
