# ALIGNMENT: 股票代码格式不一致导致的标签分裂问题 (603977 vs 603977.SH)

## 1. 问题背景
用户反馈查询股票 `603977` 时，返回的标签为 `2025-12-11`（来源为 `wencai_html_20251212...`），但系统中同时存在 `603977.SH` 关联了 `2025-12-25` 标签。这表明同一只股票因代码格式不同（纯数字 vs 带后缀）被系统视为两个实体，导致数据（标签、历史记录）分裂。

## 2. 原始需求
- **排查逻辑**：查明为什么会有两份数据，以及它们是如何产生的。
- **解决冲突**：确认正确的格式（通常应为带后缀的标准格式 `XXXXXX.SH/SZ`），并统一数据。
- **验证来源**：用户提到 `wencai_html_20251212_134753_18.html_2025-12-12`，需确认该文件导入时为何使用了不带后缀的格式。

## 3. 核心疑问与假设
- **Q1: 为什么问财解析会产生不带后缀的代码？**
  - *假设*：问财HTML解析逻辑直接使用了页面上的代码（通常是纯数字），且未进行后缀补全。
- **Q2: 为什么会有 `603977.SH`？**
  - *假设*：可能是通过其他渠道（如手动添加、Tushare同步）进入系统，或者是某些特定批次处理了后缀。
- **Q3: 如何修复？**
  - *策略*：
    1. 修改 `WencaiService` 解析逻辑，强制标准化股票代码。
    2. 数据清洗：将 `603977` 的关联数据迁移至 `603977.SH`，并删除旧记录。

## 4. 任务范围
- **调查**：使用脚本查明 `603977` 和 `603977.SH` 的所有关联数据（Tags, Relations, Batches）。
- **修复代码**：确保所有入库操作都对股票代码进行标准化（`.SH`, `.SZ`, `.BJ`）。
- **修复数据**：编写迁移脚本合并数据。
